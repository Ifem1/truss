## Diagnosis and limits

The three successful-path attempts and the fourth invalid-candidate probe all finalized with leader timeouts, not TRUSS-level errors. The three activation attempts each exceeded 600 seconds with no committed or revealed votes; the invalid probe also ended as `Leader Timeout` and cannot count as a live rejection proof. Two receipts previously described as stuck `PROPOSING` later finalized with the same timeout result. The Studionet RPC does not expose `gen_dbg_traceTransaction` (`genlayer trace` returns JSON-RPC `-32601 Method not found`), and appeal-bond calculation is unavailable because fee-manager/round-storage addresses are missing. The currently available public evidence therefore identifies a GenVM leader execution failure but cannot isolate its underlying cause.

The current contracts remain the deployed versions. The issuer-bound `TEST_STATUS` guard and expanded adversarial consumer suite passed CI but still require a new byte-matched registry deployment before they can be represented as live behavior. Issuer addresses are adopter-designated wallets, not proof of independent organizations. GitHub Actions metadata verifies GitHub's report of a run, not workflow independence, test quality, or the proposition that specific properties were tested. The activation request remains unsuccessful, and the canonical gate state remains empty.
