## Diagnosis and limits

The three finalized activation failures are not contract rejections: their leader receipts show `LEADER_EXEC_TIMEOUT`, not a TRUSS `UserError`, and no validator entered a voting round. The two receipts previously described as stuck `PROPOSING` later finalized with the same timeout result. A fourth invalid-candidate probe is currently pending without a leader, so no live rejection conclusion can yet be drawn. The Studionet RPC also does not expose `gen_dbg_traceTransaction`; `genlayer trace` returns JSON-RPC `-32601 Method not found`. Appeal-bond calculation is unavailable on this chain because fee-manager/round-storage addresses are missing. These constraints rule out diagnosing the underlying GenVM stack or forcing the pending transaction to finality from this client.

The current contracts remain the deployed versions. The issuer-bound `TEST_STATUS` guard and expanded adversarial consumer suite in the working source require CI and, if accepted, a new byte-matched registry deployment before they can be represented as live behavior. Issuer addresses are adopter-designated wallets, not proof of independent organizations. GitHub Actions metadata verifies GitHub's report of a run, not workflow independence, test quality, or the proposition that specific properties were tested.
