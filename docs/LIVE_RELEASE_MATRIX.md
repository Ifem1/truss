## Updated diagnosis and boundary (2026-10-11)

The old `LATEST_FINAL` cross-contract view path remains broken under the previously recorded low-volume probe and 600-second write receipt. The separate finalized-message primitive above now succeeds with one parent write and one finalized child. That successful live test means the project can proceed using finalized messages without substituting unfinalized state. It does not establish that the new TRUSS contracts have been deployed or that registry admission, gate activation, acknowledgments, or negative authorization paths work live. Do not treat the primitive test as full TRUSS enforcement proof.

The minimal `LATEST_FINAL` repro remains documented in [GenLayer issue #60](https://github.com/genlayerlabs/genvm-manager/issues/60); the issue is now a diagnosis of the old mechanism, not a blocker to testing the finalized-message design.

The existing production registry and gate remain unchanged during the new design's verification. The hardened registry source and the message-based gate are still not deployed. A live successful TRUSS activation, invalid-candidate rejection, acknowledgment, canonical poststate, and production cutover remain unproven until recorded in this matrix.

Production stays on the deployed addresses above. The hardened registry source is not deployed, the existing admitted release is not activated, and live invalid-candidate rejection is unproven. No frontend cutover to an empty or unverified registry occurred. The mandatory live lifecycle therefore remains **BLOCKED**.
